Phase 1 of the subtype-cohort roadmap (see `docs/development/subtype_cohort_architecture.md`) landed 2026-04-17 with byte-for-byte parity verified against the pre-refactor baseline. The `feat/phase1-cohort-refactor` branch in the kraken repo (GitHub: fhew/kraken; Azure: sotio/Kraken application) holds the full work.

**What shipped:**

- `core/cohorts.py` — `Cohort` dataclass (frozen, with `pediatric_caveat` and `normal_reference_tier` for Phase 2a) and `CohortRegistry` with YAML loaders, collision detection, expansion-model membership.
- `data/cohorts/tcga_study.yaml` — 93 compat cohorts covering every `primary_disease_or_tissue` value, 19,130 samples, generated by `scripts/generate_compat_cohorts.py`.
- `ExpressionCache.attach_cohort_registry` — LEFT JOIN on cohort_membership so samples without any cohort (e.g. NULL-disease TCGA sample) survive for individual_coverage; `cancer_data_unique = cancer_data.unique(subset=["sample_id"])` pattern collapses multi-cohort expansion when computing pair-wide metrics.
- `pair_coverage.cohort_id` column + `pair_coverage_gene` view migration.
- `pair_analyzer.process_pair` swapped from `group_by="primary_disease_or_tissue"` to `group_by=["cohort_id", "cohort_parent_indication"]`; `cohort_to_parent` dict preserves the original disease string in the `cancer_type` column for backward compat.
- Priority migration: cohort YAMLs authoritative, `indications.csv` reduced to descriptive-only (indication_name).
- 26 unit tests (`tests/test_cohorts.py`) + 7 tests (`tests/test_expression_cache_cohort.py`).
- `tests/parity_golden.json` re-captured post-refactor (3 runs: cdh17_fixed, itgb4_fixed, cdh17_lowcov).

**Why the run_id-hash fix mattered:** pre-refactor `_compute_run_id` used f-string float formatting for numeric config fields, which silently drifted between int-vs-float YAML values. Now normalized via `f"{float(x):.10g}"`. Consequence: run_ids for pre-refactor and post-refactor runs differ even when the config is semantically identical.

**How to apply:** Any future change to `pair_analyzer` or `db_writer` must re-pass `scripts/test_pipeline_parity.py verify` unless it's an intentional metric change. The golden is the load-bearing parity gate.
